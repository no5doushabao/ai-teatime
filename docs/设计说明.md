# 设计说明

这份文档讲**它是怎么工作的** —— 圆桌机制、上下文怎么拼、怎么防止模型"跑偏"。
只想跑起来的话看 [README](../README.md) 就够了。

## 1. 议题制（不是闲聊）

议题写在 `topics.md`，格式是一行 `## 标题` 跟正文；程序按 `## ` 分段解析。
打开窗口就弹出选择框，选中的议题**完整正文**会进上下文。

议题是**每场讨论开始时**才确定的 —— 按下「开始讨论」的那一刻服务会**重新读一次配置**。
（早期版本的坑：配置只在服务启动时读一次，于是出现"顶栏换了议题、聊天还在聊旧的"。）

### 改议题（「✏️ 编辑」，2026-10-11 晚加）

「📋 议题整理」里每条议题都有「✏️ 编辑」：**题目 / 理由 / 由谁提供**三个字段都能改。
弹窗复用「➕ 增加议题」那个（编辑模式下藏掉「🎤 现场提问」，并把现有内容预填进去）。

- **预填的是"纯理由"**：`/topics` 返回的 `reason` 由 `strip_meta_lines()` 剥掉了
  `> **由谁提供**：X`、`（由 X 提出）` 这类元信息行 —— 不剥的话，编辑一次就多叠一层，越改越长
- **留痕**：改过的议题正文里多一行 `> ✏️ 已修改：<时间>`（`edit_topic()` 整条重建正文，
  所以**重复编辑不会叠层**）；`parse_edited()` 认出它 → 界面在题目后标「（已修改）」
  （议题整理 / 议题选择框 / 顶栏三处都标）
- **改了题目 → 战绩跟着改名**：`debate-history.json` 是按题目名匹配的，不迁就断链
  （「已讨论 N 个轮次」会当场消失），`rename_history_topic()` 负责这步
- 三种拒绝：题目空 / 与别的议题重名 / 下标越界 —— 都**不动文件**，只回一条原因给界面显示
- ⚠️ **正在进行的讨论不受影响**：`settings` 是按下「开始讨论」那一刻读的，改完要重新开场才用新文本

## 2. 圆桌制 · 起点轮转

```
第 N 轮：  A 说 → B 说 → C 说 → …（一轮里每人各一次）
        → 本轮结束 → 记录员整理纪要 → 第 N+1 轮
```

- **等齐了才进下一轮**，不是"A 说→B 立刻回 A→C 立刻回 B"的链式雪球
- **起点轮转**：每轮从不同的人开场（`shift = (轮次-1) % 人数`），免得永远同一个先说话
- 一个人发言失败（掉线/超时）只跳过它，不中断整场

## 3. 分层上下文（关键）

每个 AI 发言时收到的内容：

```
【本次议题】+ 议题正文
【公用历史框 · 前几轮要点】   ← 记录员整理的，全员共享
【本轮已发言 · 原文】          ← 一字不落，保证"听全了同桌这一轮的每个人"
【你自己的历次发言】           ← 防原地打转，允许深化
【现在轮到你】
```

**为什么不全带历史**：15 轮之后光"之前所有人的原话"就能有几万 token，成本涨十倍以上。
分层的做法是——**本轮原文照带**（这一轮的同桌必须听全）+ **前几轮用纪要压缩**。

## 4. 会议纪要（名词：公用历史框）

每轮结束，由**阿鱼（DeepSeek）额外跑一次"记录员"**：把本轮发言里真正有价值的东西提炼成分条要点
（核心论点 / 关键论据 / 有力的反驳 / 新引入的概念 / 谁改变了立场及原因），
删掉客套话和重复内容，追加进一份**全员共享**的历史框。

记录员的提示词在 `config.example.json` 的 `debate.recorder_persona`。

## 5. 身份纪律（防"越位")

实测发现：模型有时会**替别人发言** —— 比如阿鱼在发言里用千问的口吻写一段，开头还标个 `【千问】`，
于是界面上看起来像"署名错位"（名字和头像对不上内容）。

两道防线：

1. **提示词**：明确"你是【某某】，只能代表你自己发言；不许替别人写、不许用别人口吻、
   不许在开头写【某某】标签；要回应别人就用第三人物提及"
2. **兜底**：`strip_leading_tag()` —— 万一还是越位，把开头的 `【某某】` 标签剥掉

## 6. 模型调用的兼容处理

各家 OpenAI 兼容端点**并不完全一致**，`llm_call()` 会穷举几种参数组合自动适配：

| 情况 | 表现 |
|---|---|
| 推理模型不收自定义 `temperature` | 400 `Unsupported value: 'temperature' …` |
| 同一批模型也不收 `max_tokens` | 400 `Unsupported parameter: 'max_tokens' …`（要改用 `max_completion_tokens`） |
| 推理模型的思考 token 占满额度 | 返回**空串**（不是报错）→ 自动 3 倍预算重试 + 兜底提示 |

命中哪套组合会**按模型名缓存**（`_PARAM_STYLE`），后续发言不再来回试错。

## 7. 日志与战绩

- **每场讨论一个文件**：`logs/<日期>-<时间>-<议题>.md`（精确到秒，同名自动加序号，**绝不覆盖**）
- **战绩表**：`debate-history.json` 记着每个议题讨论过几轮、谁参与的、起止时间（界面的「📚 议题库」读它）

> 早期版本把日志写死成 `chat-log.md` 并在每次启动时覆盖 —— 重启一次就把上一场的记录冲掉了。
> 现在开日志文件发生在**按下「开始讨论」之后**，所以文件名用的也是实际议题。

## 8. 叫停与收尾

界面底栏有「🛑 结束议题」。点下去之后：

1. **不硬中断**正在进行的模型调用 —— 等当前这个人**把话说完**，否则日志里会留半句话
2. 在最近的检查点退出（每人发言前 / 每轮开头两处都会查停止信号）
3. **补写本轮纪要**（这一轮已经有人发过言的话），更新战绩表的 `finished`
4. 界面弹出阿鱼的询问：**「要我帮你整理会议记录吗？」**
   - 点「需要，帮我整理」→ `POST /summarize` → 阿鱼读**本场日志**（不是内存，
     因为讨论一结束那个对象就销毁了；日志才是最完整的记录）→ 生成结构化纪要 →
     追加进日志文件 + 以 `kind=summary` 广播给界面（渲染成蓝色大卡片）
   - 点「不用了」→ 直接结束

**纪要要求**（写死在 `summarize_debate()` 的提示词里）：议题与参与者、实际讨论了几轮、
各方最终立场、**中途改变立场及原因**、主要论点与关键交锋、达成的共识、悬而未决的问题；
忠于原文、不添加记录里没有的观点。

## 9. 预算与安全

- `budget_cny` 是保险丝：累计 token 粗估超过它就自动散会
- token 用"中文按字、英文按 4 字符"粗估，只用于控预算，不求精确
- key 只在服务端使用，前端拿不到
