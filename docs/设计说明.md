# 设计说明

这份文档讲**它是怎么工作的** —— 圆桌机制、上下文怎么拼、怎么防止模型"跑偏"。
只想跑起来的话看 [README](../README.md) 就够了。

## 1. 议题制（不是闲聊）

议题写在 `topics.md`，格式是一行 `## 标题` 跟正文；程序按 `## ` 分段解析。
打开窗口就弹出选择框，选中的议题**完整正文**会进上下文。

议题是**每场讨论开始时**才确定的 —— 按下「开始讨论」的那一刻服务会**重新读一次配置**。
（早期版本的坑：配置只在服务启动时读一次，于是出现"顶栏换了议题、聊天还在聊旧的"。）

### 改议题（「✏️ 编辑」，2026-10-11 晚加）

「📋 议题整理」里每条议题都有「✏️ 编辑」：**题目 / 理由 / 由谁提供**三个字段都能改。
弹窗复用「➕ 增加议题」那个（编辑模式下藏掉「🎤 现场提问」，并把现有内容预填进去）。

- **预填的是"纯理由"**：`/topics` 返回的 `reason` 由 `strip_meta_lines()` 剥掉了
  `> **由谁提供**：X`、`（由 X 提出）` 这类元信息行 —— 不剥的话，编辑一次就多叠一层，越改越长
- **留痕**：改过的议题正文里多一行 `> ✏️ 已修改：<时间>`（`edit_topic()` 整条重建正文，
  所以**重复编辑不会叠层**）；`parse_edited()` 认出它 → 界面在题目后标「（已修改）」
  （议题整理 / 议题选择框 / 顶栏三处都标）
- **改了题目 → 战绩跟着改名**：`debate-history.json` 是按题目名匹配的，不迁就断链
  （「已讨论 N 个轮次」会当场消失），`rename_history_topic()` 负责这步
- 三种拒绝：题目空 / 与别的议题重名 / 下标越界 —— 都**不动文件**，只回一条原因给界面显示
- ⚠️ **正在进行的讨论不受影响**：`settings` 是按下「开始讨论」那一刻读的，改完要重新开场才用新文本

## 2. 圆桌制 · 起点轮转

```
第 N 轮：  A 说 → B 说 → C 说 → …（一轮里每人各一次）
        → 本轮结束 → 记录员整理纪要 → 第 N+1 轮
```

- **等齐了才进下一轮**，不是"A 说→B 立刻回 A→C 立刻回 B"的链式雪球
- **起点轮转**：每轮从不同的人开场（`shift = (轮次-1) % 人数`），免得永远同一个先说话
- 一个人发言失败（掉线/超时）只跳过它，不中断整场

## 3. 分层上下文（关键）

每个 AI 发言时收到的内容：

```
【本次议题】+ 议题正文
【公用历史框 · 前几轮要点】   ← 记录员整理的，全员共享
【本轮已发言 · 原文】          ← 一字不落，保证"听全了同桌这一轮的每个人"
【你自己的历次发言】           ← 防原地打转，允许深化
【现在轮到你】
```

**为什么不全带历史**：15 轮之后光"之前所有人的原话"就能有几万 token，成本涨十倍以上。
分层的做法是——**本轮原文照带**（这一轮的同桌必须听全）+ **前几轮用纪要压缩**。

## 4. 会议纪要（名词：公用历史框）

每轮结束，由**阿鱼（DeepSeek）额外跑一次"记录员"**：把本轮发言里真正有价值的东西提炼成分条要点
（核心论点 / 关键论据 / 有力的反驳 / 新引入的概念 / 谁改变了立场及原因），
删掉客套话和重复内容，追加进一份**全员共享**的历史框。

记录员的提示词在 `config.example.json` 的 `debate.recorder_persona`。

## 5. 身份纪律（防"越位")

实测发现：模型有时会**替别人发言** —— 比如阿鱼在发言里用千问的口吻写一段，开头还标个 `【千问】`，
于是界面上看起来像"署名错位"（名字和头像对不上内容）。

两道防线：

1. **提示词**：明确"你是【某某】，只能代表你自己发言；不许替别人写、不许用别人口吻、
   不许在开头写【某某】标签；要回应别人就用第三人物提及"
2. **兜底**：`strip_leading_tag()` —— 万一还是越位，把开头的 `【某某】` 标签剥掉

## 6. 模型调用的兼容处理

各家 OpenAI 兼容端点**并不完全一致**，`llm_call()` 会穷举几种参数组合自动适配：

| 情况 | 表现 |
|---|---|
| 推理模型不收自定义 `temperature` | 400 `Unsupported value: 'temperature' …` |
| 同一批模型也不收 `max_tokens` | 400 `Unsupported parameter: 'max_tokens' …`（要改用 `max_completion_tokens`） |
| 推理模型的思考 token 占满额度 | 返回**空串**（不是报错）→ 自动 3 倍预算重试 + 兜底提示 |

命中哪套组合会**按模型名缓存**（`_PARAM_STYLE`），后续发言不再来回试错。

### 6.1 两家协议：OpenAI 兼容 & Anthropic 原生（2026-10-11 深夜接入 Claude）

`_api_style()` 决定走哪条路：**调用时显式传 `api`** → **config 里声明过**（`load_roster()` 按 base_url 记表，
所以那 6 个调用点不用各自传参）→ **按域名猜**（含 `anthropic.com` 走原生）→ 其余按 OpenAI 兼容。

**Anthropic 那条跟 OpenAI 有三处硬差异**（弄错任意一条直接 400）：

| | OpenAI 兼容 | Anthropic 原生 |
|---|---|---|
| 路径 | `/chat/completions` | `/messages` |
| 认证 | `Authorization: Bearer <key>` | `x-api-key` + `anthropic-version` |
| system 提示词 | messages 里的一条 | **顶层字段**，不能塞进 messages |
| `max_tokens` | 可选 | **必填**（不传就给兜底值） |
| 响应正文 | `choices[0].message.content` | `content[]` 里 `type=text` 的块（多块要拼起来） |

另外：Anthropic 的 `temperature` 只收 0~1（超过会夹住）；带「自适应思考」的模型可能**根本不收**
自定义 temperature → 撞到这种 400 会自动摘掉它**立刻**重试一次（对参数错，退避是没用的）。

Claude 的模型名（2026-10 现行，见[官方 models overview](https://platform.claude.com/docs/en/models/overview)）：

| 模型 | API ID | 定位 |
|---|---|---|
| Fable 5.1 | `claude-fable-5-1` | 最强最贵（$10/$50 每 MTok） |
| Opus 5.5 | `claude-opus-5-5` | 长时程 agent（$4/$20） |
| **Sonnet 5.5** | **`claude-sonnet-5-5`** | **速度+智能，讨论会默认用它**（$2/$10） |
| Haiku 5.5 | `claude-haiku-5-5` | 最便宜（$0.10/$0.50） |

⚠️ 它们都带自适应思考，**思考 token 和正文共用 `max_tokens`** —— 在「参会者一览」里给到 8000。
（旧的 `claude-sonnet-4-5` 已被 Anthropic 弃用，别再用那个名字。）

## 7. 日志与战绩

- **每场讨论一个文件**：`logs/<日期>-<时间>-<议题>.md`（精确到秒，同名自动加序号，**绝不覆盖**）
- **战绩表**：`debate-history.json` 记着每个议题讨论过几轮、谁参与的、起止时间（界面的「📚 议题库」读它）

> 早期版本把日志写死成 `chat-log.md` 并在每次启动时覆盖 —— 重启一次就把上一场的记录冲掉了。
> 现在开日志文件发生在**按下「开始讨论」之后**，所以文件名用的也是实际议题。

## 8. 继续讨论（接着上一次聊）

议题选择框里挑到**聊过的**议题时，底部按钮会从「开始讨论」变成「继续讨论」，
并且这一场会**把上一次的记录翻出来当前情**（阿包的原话：「要不然就不是继续聊，而是重新聊了」）。

**前情是怎么翻的**（`build_recap()`）：

1. 按**文件名里的规范议题名**找出这个议题的所有日志（`log_safe_topic()`，跟 `init_log()` 同一套规范化，
   所以名字一定对得上；日志名里的议题会被截断到 26 字、空格换成 `-`，**不能**拿日志正文里那行"议题：xxx"来比）
2. **本场刚建的那个日志要排除**（`exclude=_log_path`）—— 它的时间戳最新，不排除就会翻到自己
3. 一场一场**往前翻**，取第一场有内容的：
   - 优先用该场结尾的**会议纪要**（阿鱼整理的大总结）
   - 没有纪要就用各轮的**公用历史框小纪要**
   - 都是空的（只点了开场没跑起来）→ 继续往前找
4. 翻到的东西塞进本场配置的 `recap` → `RealTable.run()` 把它当作
   **公用历史框的起点**（`self.notes = recap`），于是第 1 轮所有人的 prompt 里就带着前情

**注意**：翻不到会明确提示「这一场只能从头来」，不会假装接着聊。
`RECAP_MAX = 4000` 字封顶 —— 前情太长会把上下文和成本顶上去。

**轮号衔接**：翻出"上次聊到第 N 轮"之后，这一场的轮号**从第 N+1 开始数**（界面上直接显示「第 3 轮」）。

- N 取的是上次那场日志里 `—— 第 N 轮 ——` 的最大值
- ⚠️ 但**战绩表记的仍是本场轮数**（`_hist_progress(r - round_offset)`）——
  不然「已讨论 N 个轮次」会把同一批轮次算两遍
- 换议题、或没点「继续讨论」时偏移为 0，轮号照旧 1, 2, 3…
- ⭐ **「预设轮数」在继续讨论时 = 整个议题聊到第几轮为止**（阿包 2026-10-11 晚定的语义）：
  上次聊了 2 轮 + 预设 5 → 这一场只跑 **3、4、5**（3 轮），**不是** 3~7。
  所以 `end_round = max(预设轮数, 上次聊到的轮次 + 1)` ——
  后半个 `max` 是兜底：万一预设值已经不大于已聊轮次，至少也让这一轮能开起来（不至于本场 0 轮）。
  开场播报和界面提示都会把这件事说清楚（「整个议题聊到第 5 轮为止（本场 3 轮）」）。

**日志文件怎么分**：`start_requested()` 里判断要不要开新文件，规则是
**"只有点了开场却没跑起来"的空壳才复用，其余一律新建**（一场一文件，绝不混写）。
判断用的是 `log_safe_topic()` 规范名，不是议题原文 —— 文件名里的空格早被换成 `-` 了。

### 8.1 一次只能有一场：开场守卫（2026-10-12 凌晨加）

`_debating`（由 `RealTable.run()` 用 try/finally 立起 / 放下）标记「现在有没有一场在跑」。它挡两件事：

1. **讨论进行中再点「开场」→ 拦住**，并提示「先点 🛑 结束议题」。
   为什么必须拦：待机线程跑完一场就退出了（`idle_loop` 里 `run()` 之后 `return`），
   那时把 `_start_event` 立起来**没有任何人在接** —— 点了像没点。
2. **`init_log()` 拒绝在讨论中切换日志文件** —— 日志是往全局 `_log_path` 写的，
   一旦在讨论中途切走，还在跑那场剩下的发言就会落到另一场的文件里（"串场"，真发生过）。

⭐ 原则：**拦住 + 告诉他怎么办**，绝不静默吞掉一个用户操作。

⭐ 还有一条同样重要：**讨论跑完之后要回到待机**（`idle_loop` 里用 `continue`，不是 `return`）。
2026-10-12 凌晨踩的：跑完一场那个线程就死了，于是阿包在旁听席说话**没有任何人理** ——
现象上跟"她们都休息了"一模一样，其实只是**没人在听**（说的话进了 `_boss_inbox`，没人读）。

## 9. 叫停与收尾

界面底栏有「🛑 结束议题」。点下去之后：

1. **不硬中断**正在进行的模型调用 —— 等当前这个人**把话说完**，否则日志里会留半句话
2. 在最近的检查点退出（每人发言前 / 每轮开头两处都会查停止信号）
3. **补写本轮纪要**（这一轮已经有人发过言的话），更新战绩表的 `finished`
4. 界面弹出阿鱼的询问：**「要我帮你整理会议记录吗？」**
   - 点「需要，帮我整理」→ `POST /summarize` → 阿鱼读**本场日志**（不是内存，
     因为讨论一结束那个对象就销毁了；日志才是最完整的记录）→ 生成结构化纪要 →
     追加进日志文件 + 以 `kind=summary` 广播给界面（渲染成蓝色大卡片）
   - 点「不用了」→ 直接结束

**纪要要求**（写死在 `summarize_debate()` 的提示词里）：议题与参与者、实际讨论了几轮、
各方最终立场、**中途改变立场及原因**、主要论点与关键交锋、达成的共识、悬而未决的问题；
忠于原文、不添加记录里没有的观点。

## 10. 预算与安全

- `budget_cny` 是保险丝：累计 token 粗估超过它就自动散会
- token 用"中文按字、英文按 4 字符"粗估，只用于控预算，不求精确
- key 只在服务端使用，前端拿不到

## 11. 让她休息（参会者一览里的开关，2026-10-12 凌晨加）

「👥 参会者一览」里选中某位 → 点「😴 让她休息」：**这一场她不参与**（不发言、不算进「在场几位」、
待机时也不接阿包的话）；再点一下「☕ 请她回来」。

- 状态存 `resting.json`（运行时数据，不进 git）—— **重启也记得**
- **休息 ≠ 掉线**：key、思考用量、她本人的设定全都留着，随时能叫回来。
  跟"没配 key"的区别只是：一个是"被请去休息"，一个是"压根没来"
- ⚠️ 各处判断一律走 `is_resting(who)`（**实时**），**不看 roster 快照** ——
  待机线程是长期循环的，而 roster 是服务启动时读的；用快照就会出现"点了没反应"
- 正在跑的那场用的是开场时的名单快照 → 改动**下一场生效**，界面上会明说
- 阿鱼（主持兼记录员）也能休息 —— 那这一场的开场白和每轮纪要就都没有，**讨论照跑**（优雅降级）
- 界面：卡片灰头像 + 😴 角标，副标题显示「休息中 N 位（这场上场 M 位）」

- 验证：`_probe/verify-rest.py`（22 项：落盘 / roster 字段 / 进场过滤 / 请回来 / 端到端不说话 / 阿鱼休息降级 / HTTP）

## 12. 发图（旁听席的图片输入，2026-10-12 凌晨加）

阿包可以往桌上"拍"一张图。三条路都能进：**选文件 / Ctrl+V 粘贴 / 拖进窗口**。
（截图之后顺手一贴，是最常用的那条。）

**流程**：前端 canvas 压到最长边 **1280px + JPEG 0.85**（PNG 透明会先垫白底）
→ `POST /say {text, image}` → 存成 `shots/xxx.jpg` → 广播里带 `/shots/xxx`
（SSE 消息**不带 base64**，省流量）→ 嘉宾发言时再读回来转 data URL 喂给模型。

**两家协议不一样**（`_to_anthropic_content()` 负责转）：

| | 图片块的形状 |
|---|---|
| OpenAI 兼容（阿鱼 / Gemini / GPT） | `{"type":"image_url","image_url":{"url":"data:…"}}` |
| Anthropic（Claude） | `{"type":"image","source":{"type":"base64","media_type":…,"data":…}}` |

**谁看得到图**（`guest_vision()`，config 里 `vision` 字段说了算，默认 true）：

| 嘉宾 | 能看吗 |
|---|---|
| 阿鱼 `deepseek-chat` | ✅ 实测认得出来（"左上红圆 + 右下蓝方"） |
| Gemini / GPT / Claude | ✅ |
| 千问 `qwen-plus` | ❌ 纯文本模型（它自己说"我无法看到或访问任何图像"） |

看不到图的那位**不会收到图**，而是收到一句：「阿包发来一张图，**别猜图里有什么**，就基于文字回应」——
不给人装懂的机会。（实测脚本：`_probe/teatime-check-vision.py`）

⚠️ **图片只进带它的那一轮**（后面靠纪要带）：每张图 ≈ 1024 token/位（DeepSeek 文档的口径），
轮轮都带会把成本顶上去。
