# 踩过的坑

开发过程中真实踩到并修掉的坑，记下来免得重犯。

## 1. 浏览器缓存：改完界面一直显示旧页

`chrome --app` 窗口会缓存页面。更坑的是 **PowerShell 的 `Invoke-WebRequest` 自己也有缓存** ——
用它验证会得到"文件没更新"的错误结论（我就这么被骗过一次，白白排查半天）。

- **验证网页内容用 `curl`**，别用 `Invoke-WebRequest`
- **根治**：启动器给 URL 加时间戳（`?t=20261010161927`），每次都是"新地址"，浏览器想用缓存都没得用
- ⭐ **2026-10-12 又补了两道**（这天为了"改了没生效"来回折腾过好几轮）：
  · `/`（界面）不再交给静态处理，改由 `_serve_index()` 自己发，带 `Cache-Control: no-store`
  · 页面里写死 `PAGE_VERSION`（服务端渲染时替换），跟 `/state` 返回的版本一比 ——
    对不上就在右上角标红「页面 v0.2.0 → 服务 v0.2.1：按 Ctrl+F5 刷新」。
    **现在"改了没生效"不用猜是服务端还是页面了**

## 2. 推理模型的"思考 token"会吃光输出额度

`gpt-5` 系列是推理模型：它先"想"再"说"，而**思考的 token 也算在 `max_completion_tokens` 里**。
设 1200 时思考就吃光了，**返回空串**（不是报错！）→ 界面上表现成"卡住不出声"。

- 实测：`max_tokens=1200` → 输出 **0 字**；`max_tokens=4000` → 输出 **1194 字**
- 现在默认给 4000，并对空回复自动重试

## 3. 各家参数不统一

GPT-5 系列**不收自定义 `temperature`**（只允许默认值 1），**也不收 `max_tokens`**（要 `max_completion_tokens`）。
`llm_call()` 改成穷举参数组合（`t_tok` / `t_ctok` / `ctok` / `tok` / `t` / `plain`），
撞到"参数不支持"就换下一套，命中后按模型名缓存。

## 4. 空回复必须报警

以前 `llm_call()` 返回空串，代码就直接"说"了句空话 —— 界面上什么都没显示，
看起来像"这个 AI 卡住了"。现在：空回复 → 3 倍预算重试 → 还不行就给一条明确的提示。

## 5. 配置缓存导致"换了议题不生效"

`settings` 是服务启动时读一次的。界面上换了议题、后端还在用旧配置 → 顶栏显示新议题、讨论聊旧的。
**修法**：按下「开始讨论」时重新读一次配置。

## 6. 模型会"越位"替别人发言

模型有时会用别人的口吻写一段，还在开头标 `【千问】` → 界面上看起来像"署名错位"（头像和名字对不上内容）。
**修法**：提示词加"身份纪律" + `strip_leading_tag()` 兜底剥离。

## 7. 日志被覆盖（丢过一次真实数据）

早期 `main()` 每次启动都 `write_text` 重写 `chat-log.md` —— **重启一次服务就冲掉上一场记录**，
丢过一整场 543 行的讨论。现在每场一个文件、精确到秒、同名加序号。

## 8. `.ps1` 必须存成 UTF-8 with BOM

PowerShell 5.1 读**无 BOM** 的 UTF-8 文件时会按 GBK 解码 → 中文注释把语法撑坏 →
`ParserError: Unexpected token`，双击快捷方式毫无反应。

- 存成 `utf-8-sig`（带 BOM）
- ⚠️ **用编辑器/脚本改完 `.ps1` 之后要重新加 BOM**（我一天犯了两次）
- ⭐ 教训：**交付给人双击的脚本，写完必须自己实跑一次**

## 9. 改代码时的手滑（我的）

用 `edit` 插入代码时，如果 `old_string` 只写"函数头 + 下一行"、`new_string` 只写"函数头"，
**等于在删中间的行** —— 我因此误删过两次 `load_settings` 的开头。

- **插入代码时，`old_string` 和 `new_string` 都要包含完整的原代码**
- **改完立刻跑自测**

## 10. 自测要覆盖到新函数

加了 `strip_leading_tag()` 但自测没覆盖它 → 漏了 `import re` 都没发现，直到真跑才崩。
补了三条断言后，**第一次跑就把这个 bug 抓出来了**。新函数顺手加断言，成本极低。

## 11. 本地绝对路径别写进代码

`run.ps1` 里写死过 `C:\Users\<用户名>\.dsh\...\python.exe` —— 既暴露隐私，别人拿到也跑不起来。
改成按优先级探测（环境变量 → 已知位置 → PATH）。
**提交前扫一遍 `sk-` / `C:\Users` / `D:\` 之类的模式。**

## 12. 阿包插话的那一轮会"跳过暂停"

手动模式下每轮讲完都该停下等「▶ 开始下一轮」，但**阿包插过话的那一轮**讲完不停，
按钮根本不出现、直接开了下一轮。阿包 10-11 晚当场看出来的原话：
"第一轮结束的时候顺利的出现了进入下一轮的按钮，但是进入之后，第二轮没有显示这个按钮
而是直接开启了第三轮。"

- **真因**：`run()` 里"阿包插话"分支末尾是一句 `continue` —— 它**绕过了手动模式的等待逻辑**
  （那个 bug 之前的等待代码是写死在主流程尾部的，插话分支走了另一条路）
- **修法**：把"停下 / 收工（结束议题、超预算）"抽成 `RealTable._pause_between_rounds()`，
  普通轮和插话轮**都调它**，两条路只有一份收尾逻辑
- ⭐ **教训**：同一个循环里的两条分支，收尾逻辑必须共用一份 ——
  复制粘贴出来的分支，最容易漏掉后来才加的规则（手动模式是新加的，
  加的时候只想到主流程，忘了插话这条捷径）
- 复现脚本：`_probe/verify-interject-pause.py`（mock LLM，跑 3 轮，
  分别验"普通轮停 2 次 / 插话轮也停 2 次 / 自动模式停 0 次"）

## 13. 新开的日志文件会被当成"上一次"

做「继续讨论」（挑到聊过的议题 → 接着上次聊）时踩的，**两层**：

① 开场流程是**先 `init_log()` 建本场日志、再回头翻"上一次"**，而新建的文件名时间戳是**最新的**
   → "上一次"永远翻到**它自己那个空壳** → 前情提要恒为空。
   **修法**：`build_recap(topic, exclude=_log_path)`，把本场文件排除掉。

② 光排除还不够：最近那场要是"**点了开场、一轮都没跑起来**"的空壳，照样翻不出东西。
   所以 `build_recap()` 改成**一场一场往前翻**，直到翻出有纪要的那场。
   （实测他那 6 场"AI 叛乱"日志里 **5 场是空壳**，真正有内容的是 19:27 那场 —— 不往前翻就等于没有。）

- ⭐ **教训**：写"找最近的那一份"这类代码时，先问自己一句
  **"我刚创建的东西，会不会被自己选中"**
- 验证脚本：`_probe/verify-resume.py`（第 ⑧ 组专门盯这个：本场空壳 + 更早的真记录）

## 14. "排除本场"排除过头了

修完第 13 条当晚，阿包立刻撞上新的一层：**聊完两轮 → 点「继续讨论」→ 界面提示"没翻到上一次的记录"**。
真因有两半，凑在一起才发作：

① `exclude=_log_path` 排的是"当前这个日志路径"。可**同一议题重开时服务端不会新建文件**，
   于是 `_log_path` 恰恰就是**刚聊完那场**（有内容）→ 把要翻的记录本身排除掉了。
② "要不要新建文件"的判断是 `want[:18] not in str(_log_path.name)` —— 拿**议题原文**比**文件名**，
   而文件名里的空格早被 `init_log()` 换成 `-` 了。含空格的议题永远比不中（每次新建、空壳堆积）；
   不含空格的（"善待AI，是否会…"）则一直复用上一场那个**已经有内容**的文件。

**修法**：

- 只有**真的新建了**文件才排除（`fresh` 标志）
- 判断一律走 `log_safe_topic()` 规范名；而且**只有"点了开场没跑起来"的空壳才复用** ——
  已经聊过的文件一律新建，免得两场记录混进同一个文件

⭐ **教训**：**"文件名"和"用户输入"从来不是一回事** —— 空格、非法字符、截断都会被规整过。
要比就得两边都过同一个规范化函数。

- 验证：`_probe/verify-resume.py` 的 ⑨ / ⑨b 两组专门盯这两个分支

## 15. 讨论进行中再点「开场」→ 点了没反应，还把日志搞串

2026-10-12 凌晨，阿包在界面上选新议题点「开场」，我同时用 API 也开了一场 —— 撞在一起：

- **他那场根本没跑起来**，界面上却像是开过了
- **我那场的发言被写进了他的议题日志**：他那边文件名叫新议题，内容却是旧议题的发言

真因两条：

1. 待机线程跑完一场就 `return` 了（`idle_loop` 里 `run()` 之后），而 `start_requested()` 只是
   `_start_event.set()` —— **那个事件没有任何人在接**
2. `broadcast()` 是往**全局 `_log_path`** 写日志的；`start_requested()` 一被调用就 `init_log()`
   切文件 → 还在跑的那一场，后面所有发言都落进了新文件

**修法（两道闸）**：

- `_debating` 标志（由 `RealTable.run()` 用 try/finally 立起 / 放下）：**讨论进行中直接拦住开场**，
  并明确提示「先点 🛑 结束议题」—— 不静默失败，也不替他中断正在说话的人
- `init_log()` 里再兜一层：讨论进行中**拒绝切换**日志文件

⭐ **教训**：**「点了没反应」是最糟的失败方式** —— 它让人以为成功了，于是继续操作，把状态越搅越乱。
**拦住 + 说清楚怎么办，永远比静默吞掉好。**

- 验证：`_probe/verify-debate-guard.py`（15 项：拦住 / 两道闸 / try-finally 复位 / HTTP 返回 ok=false）

## 16. 讨论跑完了，但"待机"没回来 —— 说话没人理

2026-10-12 凌晨，阿包跑完 10 轮闺蜜局，在旁听席说「两位聊的开心吗」——**没人理**。
他截图问：「讨论结束过后是否大家就自动全部休息了，她俩好像看不见我的话了」。

真因跟第 15 条是**同一个**：`idle_loop` 里跑完一场就 `return`，那个线程死了。
他说的话会进 `_boss_inbox`，但**没有任何人在读它**（`RealTable` 只在讨论期间读）。

- 现象上特别容易误判成"她们都休息了"—— 其实她们好着呢，只是**没人在听**
- **修法**：`idle_loop` 跑完一场**回到待机**（`continue`），不是 `return`；
  顺手把 `_start_event.clear()`（消费掉这次开场）和 `_stop_event.clear()` 做掉，
  并重新播报一次「这一场结束了，回到待机 —— 在场：…」
- 连带修：`summarize_debate()` 在 `_last_log_path` 丢了（服务重启会清掉）时，
  去 `logs/` 里挑**最近修改且真有内容**的那个 —— 不然重启之后连"整理刚才那场"都做不了

⭐ **教训**：**「没有人在听」和「大家都不在」看起来一模一样**。
一个长期循环里的 `return`，等于把"待机"这个状态整个取消了。

- 验证：`_probe/verify-idle-return.py`（10 项：跑完活着 / 说话有人回 / 能开第二场 / 重启后仍能整理纪要）

## 17. 议题整理里拖动排序之后再编辑 → 改的是**别人**那条

阿包 2026-10-12 的原话：「如果我们在议题整理里面调整了某个题目的位置，然后再进行编辑的话，
如果不编辑标题，则会查出该议题已经存在！」

真因：议题一览的拖动**只挪 DOM 节点**（这是故意的：重建列表会把正在拖的那个元素销毁），
而每条元素身上的 `dataset.index` 是**加载那一刻**从 `/topics` 拿到的原始下标；
服务端却已经按新顺序重写了 `topics.md`。于是排完序再点「✏️ 编辑」，
前端拿**旧下标**去请求，服务端取到的 `items[i]` 就是别人那条：

- 题目一个字没改 → 撞上判重 → 弹「已经有同名的议题了」（**他报的就是这个**）
- 题目改成库里没有的新名字 → **静默改错条目**：把别人那条的题目和理由一起覆盖掉（更坏，我复现出来的）
- 点「🗑 删除」→ 删掉别人那条（同一根因，他还没撞上）

**修法（两道闸）**：

1. **前端**：拖动结束、`/topics/reorder` 成功之后**重新读一遍议题库**（`showLib()`）——
   把界面手里的顺序和下标一起对齐（拖动已经结束，重建列表不会打断拖动）
2. **服务端**：`/topics/edit`、`/topics/delete` 多收一个 `expect`（界面上那条的**题目**）——
   下标指到的不是这条就**直接拒绝**，宁可不动，也绝不改错人 / 删错人

⭐ **教训**：**"下标"这种一次性凭证，只要列表还可能被重排，就不能跨操作复用**。
拖动结束的那一刻，就该让界面手里的下标重新对齐；服务端再拿"题目"当保险丝，两道一起上。

- 复现：`_probe/teatime-2026-10-12/repro_topic_edit.py`（改前必现：报同名 + 静默改错 + 删错）
- 验证：`_probe/teatime-2026-10-12/http_verify.py`（起临时副本服务打真接口：旧下标被拦、对齐后成功）
- 自测新增 13 项（拖动 → 旧下标编辑被拦 → 库没被动过 → 新题目也被拦 → 对齐后才放行 → 删除同理）

## 18. 待机回复没钉身份 → Gemini 把「克劳德」的设定认领了

阿包 2026-10-12 那场（二创社区）散场后，他在旁听席一口气点评了五位的二创形象；
日志里 Gemini 那条却是：「橘发捧书的形象我很喜欢，不过**把封号的锅扣在我头上**、
硬说我"腹黑"，阿包你也太会迁怒了吧？」—— 橘发抱书、腹黑、"你们公司老喜欢封禁中国用户"，
**全是克劳德的设定**。它认错人了。（他说"gemini 突然自认为是克劳德了，这有点怪"。）

待机回复这条路（`idle_loop`）原来的 system 只有干巴巴一句「你是Gemini。」，三个毛病：

- **没给在场名单** —— 它不知道自己这一桌都有谁
- **没说**"阿包那条消息在点评好几位，**只有写着你的那部分才是你**"
- 更糟：那句**写给人看的注释**「（旧文案写着「其他人还没到」，害**小克**当众说错了话）」
  把**别人的绰号**（小克 = Claude）留在了对它说的话里 —— 它很容易以为"小克"就是自己

**对照实验**（`_probe/teatime-2026-10-12/repro_gemini_identity.py`）：
拿**一模一样**的 prompt 打 4 次，**4 次都认得自己**（正确认领"蓝色猫娘"、把克劳德当第三人称）
→ 属**偶发漂移**，不是稳定 bug。所以修的是"诱发条件"，而不是某一行代码：
待机 prompt 抽成 `idle_system_prompt()`，补上**在场名单** + 「只有明确写着「Gemini」的那部分才是在说你」
+ 删掉"小克"绰号；加了澄清的那一组，一次就正确认领了猫娘。

⭐ **教训**：**给模型看的 system 里，别留"写给人看的注释"** —— 它分不清哪句是对它说的，
里面提到的人名 / 绰号会被它当成自己。（正式讨论那条路 `ask()` 里有完整的「身份纪律」，所以从没出过这种事。）

顺带修：`GUESTS` 那张 `who → 名字/组织` 的显示表里**一直漏着 gemini**（还有 glm / 小流），
所以日志里它一直写小写的 `**16:35 gemini**`，而别人都是 `Claude`、`GPT` ——
排查身份问题时白绕了一圈。**config 里加人，这张表也要加。**

## 19. 讨论结束后，待机闲聊"像什么都没发生过"

阿包 2026-10-12 的原话：「如果讨论结束了，大家是回归讨论还没开始的等待状态，这是不对的。
明明大家刚刚已经经历过了一次很长很长的讨论了，最后的茶会闲聊却又恢复了什么都没说过的时候。」

真因：`idle_loop` 里待机回复的上下文**只有阿包那一句话**（system 里也只有一句身份声明）——
刚聊完 5 轮的议题、各自的立场、阿鱼每轮写进公用历史框的纪要，**一个都没带**。
所以她们一散场就"失忆"、表现得像第一次见面；同一批回复之间也互相看不见
（千问刚说"克劳德腹黑？"，Gemini 那边压根不知道 —— 这也是第 18 条那个"认错人"的温床）。

**修法**：

- **散场就留「余味」**：`RealTable.run()` 的 finally 里调 `remember_debate()`，记下
  议题 / 每轮纪要 / **每个人自己最后两段发言**，落盘 `afterglow.json`
  （finally 里调 = 跑完 / 被「结束议题」掐掉 / 超预算 / 半路抛异常，哪条路散场都留得下）
- **待机回复带上它**：`idle_system_prompt(..., afterglow=…)` 里明确写
  "你**记得**这一场 —— 阿包是接着刚才的讨论跟你说话的，别当成第一次见面、也别重新自我介绍"
- **同一批闲聊互相看得见**：`note_idle_talk()` 按顺序记最近 6 条（单条截 200 字），
  后回复的人能在 prompt 里看到前面的人说了什么
- **重启也记得**：阿包双击启动器就是重启服务 —— 待机启动时先读 `afterglow.json`，
  读不到就 `afterglow_from_logs()` 从最近一场**真有内容**的日志里捡回来
- 空壳场（点了开场、一句没说）**不覆盖**上一次的余味

⭐ **教训**：**"状态回到待机"不等于"记忆回到零"**。一个长期循环里，
凡是"这一场攒下来的东西"，散场时都要显式交接出去 ——
不然它随那一场的局部变量一起消失。

⭐ 顺带踩到的小坑：从日志里捡发言时，**末尾那张「会议纪要大卡片」是多行文本**
（`say("ayu", …, "summary")` 会把整篇纪要写进日志），逐行扫会被当成"阿鱼最后说的话"——
实测真日志里 `mine["ayu"]` 就抓成了 `# 会议纪要：二创社区…`。先把纪要段落切掉再扫。

- 验证：`_probe/teatime-2026-10-12/verify_afterglow.py`（mock 模型真跑一场 → 余味落盘 → prompt 带上 →
  重启读回 → 连 `afterglow.json` 删掉也能从日志捡回）；
  `read_real_afterglow.py`（拿**今天那场真日志**只读验证：议题 / 5 轮 / 2167 字纪要 / 各人最后发言）；
  自测新增 17 项（共 45 项）

## 20. 「继续讨论」像重新开始：只接了"纪要"，没接"**你自己**说过的话"

阿包 2026-10-12 的原话：「我新跑了一轮上面的议题。怎么感觉大家似乎又回到了第一轮的样子，
好像之前没讨论过。不知道这是不是我的错觉。」**不是错觉。**
他还补了一句：「阿鱼的开场白，如果是已经讨论过的议题的话，她就应该提一嘴，
这是继续的讨论，而不是像新开了一个议题一样开场。」

先把"不是错觉"钉死：日志里 `📜 接着上一次聊 —— …本场从第 6 轮接着数`、`—— 第 6 轮 ——` 都在，
**续场机制本身是好的**。问题出在两处上下文：

① **公用历史框里只有"阿鱼整理的会议纪要"** —— 那是第三方口吻的总结，模型不把它当"我说过的话"；
   而 `my_history()` 只翻**本场**的发言（`self.by_guest`），续场时本场刚开始、它是空的
   → 每个人从自己的立场**从头再讲一遍**（实测：阿鱼第 6 轮的发言和第 1 轮几乎一样，
   她自己还在标题里写着"第1轮发言"）。
   **修法**：`start_requested()` 续场时用 `previous_speeches()` 把**各人自己**上一次的最后两段发言
   接进 `by_guest` → 落到 prompt 的「你自己的历次发言」里；prompt 里再加一条
   「【这是续场】…**接着自己的立场往前推**，别把讲过的从头再讲一遍」。

② **开场白 prompt 压根不知道这是续场** —— 它只被告知"宣布议题、讲规则、引出争点"，
   于是照着新议题的模板开场。
   **修法**：`round_offset > 0` 时给主持人的 prompt 加硬要求：
   必须**明确说出**这是接着上次继续聊（上次聊到哪儿、这回往哪推），
   不许像第一次开这个议题那样介绍背景。

⚠️ 抽"上次各人说过的话"时又踩了两个小坑（都收进 `_cut_after_debate()` 一起修了）：

- 末尾那张《会议纪要（阿鱼整理）》是**多行大卡片** → 会被当成"阿鱼最后说的话"
- **散场后的待机闲聊**顶着最后一轮的轮号 → 会被当成"讨论里的立场"（明明是闲聊）

⭐ **教训**：**"共享上下文"和"我的上下文"是两回事**。给一整桌人喂同一份纪要，
不等于每个人都记得自己说过什么 —— 要接着聊，得把**各自那条线**也接上。

⭐ 补一刀（阿包当天追问「为什么阿鱼发言一上来就是『阿鱼的第一轮发言』」）：
**prompt 里从来没告诉过她"现在是第几轮"** —— `_round_no` 只用于界面显示，模型看不到。
续场时她手里只有"上次聊到第 5 轮"和一堆旧发言，就自己猜成"第 1 轮"，
还在开头标了个 `# 阿鱼 · 第1轮发言` 的大标题。修法两头：

- `ask()` 里把当前轮次喂准：`【当前轮次 · 续场】这是本议题的第 6 轮（上一次那场聊到第 5 轮，本场接着往下数）`，
  并在 system 里禁止她自己写"第 N 轮发言"这类标题
- 兜底 `strip_self_title()`：首行同时含「第 N 轮」和「发言」就剥掉（**只动首行**，
  正文里的 `# 立场：…` 不许碰）—— 模型偶尔还是会写，剥了界面上就干净

- 打印"她现在实际收到的 prompt"：`_probe/teatime-2026-10-12/show_resume_prompt.py`
  （拿真日志的纪要 + 各人上次发言，照第 6 轮的真实情形拼一遍，不调模型）

⭐ 当天晚些时候他拍了板，这条又往前走了一步：**光喂"一份"不够，要两份一起喂** ——

> 「阿鱼不是会整理每一轮大家的发言吗？然后最后会生成一个总览。
> 我想说的就是，续读和结束时的闲聊给大家喂的就是这两部分。」

于是改成：

- `build_recap()`：**① 逐轮整理 + ② 会议总览都带上**。逐轮取**最近一场**的，总览**往前翻**到
  最近一份有的（最近那场只跑了 1 轮、又没点「帮我整理」时就得往前翻）——
  两份可能来自**不同场次**，所以各自标上时间，别让读的人以为是一场的
- `remember_debate()`：余味里加 `summary` / `summary_from`（散场那刻还没有总览，同样往前翻）
- `summarize_debate()`：生成完之后**回填**进余味（这样"刚整理完"和"散场闲聊"两头都对得上）
- `afterglow_from_logs()`（重启兜底）：也一样两份都捡
- 上限：逐轮 2000 字 + 总览 4000 字（合计 6000）—— 两份都进**每一轮**每个人的 prompt，
  实测一场多花不到 1 块钱（`budget_cny = 5.0` 里头）

⚠️ **为什么不能"只在开场发一次"**：模型是**无状态**的，每一轮都是新的一次 API 调用 ——
只发一次，第二轮它就当没读过。

- 验证：`check_recap_two_parts.py`（拿**真日志**跑：逐轮来自 16:55 那场、总览来自 15:52 那场，
  共 4161 字，两份都在）；`verify_resume_context.py`（端到端断言嘉宾 prompt 里两份都在）
- 自测新增 9 项（共 62 项）

- 验证：`_probe/teatime-2026-10-12/verify_resume_context.py`
  （mock 跑两场：① 嘉宾 prompt 带【这是续场】+ 自己上次的话 ② 开场白被要求"说出这是继续讨论"
  ③ 新议题**不**带这些 —— 别误伤）；
  `check_source_rule_and_speeches.py`（拿真日志抽 5 位 × 最后两段，确认抽到的是讨论发言而非闲聊）
- 自测新增 3 项（共 48 项）

## 21. 举例子要给出处（阿包 2026-10-12 定的新规矩）

阿包的原话：「加一条规矩吧，如果举出具体的例子的话，需要写出参考文献或者新闻的网址等。
我发现千问好像经常举一些没有来源的例子。到底是真的还是假的非常的无从考证。」

（这不是 bug，是**规则**，所以改的是配置：`debate.style` 的第 ⑥ 条 —— 它会拼进每个人的
system prompt，所以**不用改代码**；`recorder_persona` 里也让阿鱼把"无出处的例子"单列标出来。）

- ⑥ 举了具体例子**必须给出处**：机构或作者 + 标题 + 年份，有网址就贴网址；想不起确切出处
  就别当事实讲（明说"这是我推测的"），或换一个你能给出处的例子；**绝对不许编造来源**
- 记录员每轮纪要里另起一行标 `⚠️ 无出处：某某提到的「…」` —— 界面上直接看得见

⚠️ 注意：`style` 是 `start_requested()` 里**重读**的（每次点开场都会 load_settings），
所以改完**不用重启服务**；但 `roster` 是启动时读的，改嘉宾名单仍然要重启。

⭐ **教训**：模型编来源比不给来源更危险 —— 规则里必须把"不许编"写死，
而且要给一条**能下的台阶**（"想不起就说这是我的推测"），不然它为了满足规则就只好编。

### 📉 2026-10-15 追记：这条规则**实测起了反效果**

阿包两天后反馈：「千问还是照编，编法典编新闻编事件」。于是按"每千字里的硬引用次数"做了前后对比
（`_probe/teatime-ref-beforeafter.py`）：

| 谁 | 加规则前 | 加规则后 |
|---|---|---|
| 千问 | 1.21 | **1.57** |
| Claude | 0.26 | **1.13** |
| Gemini | 0.10 | **0.71** |
| 阿鱼 | 0.06 | **0.66** |
| GPT | 0.26 | 0.10 |

**全员上升**（阿鱼 11 倍），只有 GPT 降。原因：规则隐含「**你必须有一个来源**」，
而"想不起出处"那句台阶**写得太弱**，被开头的"**必须**给出处"盖过去了 ——
模型于是选择"造一个更像真的"，而不是承认想不起。

**改法（2026-10-15 重写第 ⑥ 条）**：

- 先把「必须」两个字撤掉：明确「举例子**不是必须的**」
- 把台阶**提到前面**、写成独立一条：「**想不起出处就直说想不起** —— 这是合格发言，不丢分」
- 「拿不准名字就**别写名字**」（用"有一项研究显示…"代替编一个报告名）
- 记录员那条也从"标无出处"改成"标 **⚠️ 待核实**"，且写要点时要写成「某某声称…」——
  假引用一旦进了公用历史框，后面所有轮次都会当真（**编造会接力**：千问编 → Claude 引 → 阿鱼再引）

⭐ **补一句更狠的教训**：**「要求给出处」和「要求别编」是两件相反的事。**
不给出口的硬要求，只会让假话穿上一件更像真的外套 ——
而**带来源的假话，比不带来源的更难识破**（这才是真正危险的地方）。

## 22. key 的备份差点被推进 public 仓库（阿包 2026-10-13 自己发现并修的）

他备份 key 时，备份文件名是 `keys.local.20261013-2237.json` —— 名字里**多了个时间戳**，
而 `.gitignore` 里那条是 `keys.local.json`，**匹配不上**。于是它在 `git status` 里是个待提交的新文件，
差一点点就跟着下一次提交进了公开仓库。他自己跑 `git check-ignore` 当场验出来的。

**修法**（commit `6450a40`）：

- `.gitignore` 加一整条目录 `_backup/`（备份都放那儿），而不是再加一条文件名
- `keys.example.json` 里写明「⚠️ 这是**模板**，不是你要改的那份」+「本地备份放 `_backup/`」
  （他说自己就点错过一次，打开模板一看"key 全没了"，虚惊一场）

⭐ **教训**：**`.gitignore` 的"文件名精确匹配"挡不住"带后缀的兄弟文件"**。
凡是可能被复制 / 加时间戳 / 改名备份的敏感文件（key、凭据、快照），
排除**目录**比排除**文件名**稳得多。

自查两招：`git status --short` 里挨个看 `??` 的新文件；或者 `git check-ignore -v <文件>` 问一句
"你到底被排除了没有"。**推 public 仓库之前，这一步不能省。**

## 23. 拿坐标盲点鼠标 = 点到**别人的窗口**上（阿鱼 2026-10-14 踩的）

换 README 截图时想"点一下界面上的按钮"（把议题框关掉再截聊天流）。用 `control.ps1` 报了
`MOVED 637,947 (asked 662,925)` —— **坐标被系统缩放过了**（DPI），而且 `click` 报的落点
又是第三个数（617,957）。结果那一下**点在了阿包开着的另一个窗口上**（一个浏览器窗口），
议题框纹丝没动，人家的窗口被提到了前台。所幸落点是空白处，没点到任何按钮。

⭐ **教训**：

- **坐标点击是"盲的"**：DPI 缩放 + 窗口 z-order + 前台窗口是谁，三样只要有一个不对，
  点下去就打在别处。**报出来的坐标和实际落点可能不是一回事** —— 别拿它当"我知道了"。
- **优先用"不需要点"的办法**：这次最后是靠**无头浏览器**（`chrome --headless=new`）截的 ——
  它不开窗口、不动鼠标、不影响用户桌面。踩到的两个坑也记一下：
  · 页面有 **SSE 长连接**时，无头浏览器会一直等"加载完成"不退出 → 要加 `--timeout=<ms>` 强制截
  · `--timeout` 是**从进程启动算起**，给太短会截到弹窗的淡入动画中间态（半透明叠加）
- 真要动鼠标时，**先 `-Mode cap` 看当前位置、move 之后再 cap 确认落点**，别一步到位。
- ⚠️ 我起 headless 之后用 `job_kill` 收尾，**连它启动的临时服务一起杀了**（进程树），
  后面截图一直 `ERR_CONNECTION_REFUSED`，白排查一轮 —— **杀后台任务前先想清楚它的子进程**。

（顺带：无头浏览器不吃 `backdrop-filter`，带模糊遮罩的弹窗截出来是"半透明叠加"的怪样子；
宁可改用不带遮罩的页面截，别硬调。）
